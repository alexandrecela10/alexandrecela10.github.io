BDC Mark Tape

Public BDC filings turned into one loan tape: spread comparables for pricing, a lowest-mark review list for monitoring. Every number links to its SEC filing.

Private creditDirect lendingPublic SEC dataPrototype

Project codename: Parallax.

Problem

A direct lender prices and monitors private loans without seeing how other lenders price and mark the same credits, so spreads go to committee on anecdote and a borrower other lenders have marked down waits for review.

For

PlayerMid-market direct lender or private credit fund (the PRD's worked example is an underwriter at a mid-market direct lender)
UserDeal underwriter: which spread to defend at investment committee for a borrower in a given industry
UserMonitoring analyst: which 15 borrowers get review time this quarter
BuyerHead of credit (assumed, not in the source docs): whether to fund the tape and the analyst time to run it

User stories

  1. As a deal underwriter pricing a private credit loan, I want comparable BDC spreads and marks for a filed industry label, with the contributing lenders and the source rows, so that I can defend a spread at committee and see when the "market" is one lender's book.
  2. As a monitoring analyst, I want a quarterly review list sized to what one analyst can review, lowest lender mark first, with what changed and a link to each filing, so that my limited review time goes to the names lenders already mark down.

Try it

  1. Run it locally: pip install -r requirements.txt, then streamlit run app/two_stories.py from the showcase folder.
  2. Price a loan: pick Software, first_lien. Read positions and lenders before the median. Switch to Software and Services to see the one-lender-book warning.
  3. Review list: pick 2025-12-31 and 15 names. Open one name to see each lender's mark and filing, then read the hindsight check below the list.

Data: real public SEC filings, static snapshot of 2026-09-06. No LLM, no model score, no login, no network call except SEC links you choose to open. Costs $0 to run.

Value equation

value = (outcome x likelihood) / (time delay x effort & sacrifice)

DEAL UNDERWRITER

Outcome
"My spread sits at the median of 90 first-lien insurance positions across 4 BDCs, here are the rows."
Likelihood
MEDIUM. Rows and filings are checkable. Many labels are thin: Software first lien has 5 positions from 2 lenders. Untested with underwriters.
Delay
LOW. Answer on selection from a static file. Latest quarter in the snapshot is 2026-06-30, snapshot dated 2026-09-06.
Effort
MEDIUM. Must guess which filed label matches the borrower. Labels are never merged.
Sacrifice
LOW. Public data only. Gives up an all-in yield: fees and OID aren't in the filings.

MONITORING ANALYST

Outcome
"My 15 names this quarter are the ones lenders mark lowest, with what moved and the filing one click away."
Likelihood
LOW-MEDIUM. In hindsight 3 of 15 (2025-12-31) and 1 of 15 (2026-03-31) went non-accrual next quarter. Wide intervals.
Delay
HIGH. The list needs the next filing to show its outcome: one quarter.
Effort
LOW. One list, sorted, sized to capacity.
Sacrifice
MEDIUM. Covers only names held by 8 BDCs, not the analyst's own book. Gives up a learned score.

Verdict: the weakest factor is likelihood for all three. Cheapest fix for the underwriter: put screen 1 in front of two underwriters and count who'd bring it to committee, which the PRD already names as the test. Cheapest fix for the analyst: show the hindsight check for every quarter beside the list, which the demo now does, so belief rests on outcomes for any of 7 quarters rather than a claim. For the buyer: fix the failed release checks before any adoption talk.

Sub-problems
  1. No tape. Marks and spreads sit in 64 HTML filings with 8 different table layouts.
  2. Names don't match. The same borrower is spelled differently by each lender, so marks can't be compared.
  3. Comparable set is opaque. A spread number without lenders and rows can't be defended at committee. (Story 1)
  4. One lender looks like a market. Each BDC names industries its own way, so most label buckets are one lender's book. (Story 1)
  5. Review list isn't sized or ordered. An analyst with capacity for 15 names has no ranked list. (Story 2)
  6. What changed is hidden. Mark moves, lender disagreement and new entries need a quarter-on-quarter diff and the filing. (Story 2)
  7. Warning before the mark falls. Predicting non-accrual earlier than the lowest mark does.
  8. All-in pricing. Fees, OID and call terms aren't in the schedules.
  9. Coverage. Only 8 BDCs and 8 quarters; no banks, private funds or sponsor identity.
  10. Allocator mark check. Whether a manager's mark agrees with other holders of the same borrower.
  11. Label mapping. One shared industry taxonomy across lenders.

How it works
  1. SEC EDGAR 10-K and 10-Q for ARCC, OBDC, FSK, GBDC, MAIN, TSLX, HTGC, PSEC -> cached HTML -> filing index of 64 filings.
  2. Cached HTML -> Schedule of Investments finder and table parser -> 42,830 position rows with spread, principal, cost, fair value, non-accrual flag, accession.
  3. Borrower names -> normalise, block, fuzzy score, connected components at threshold 93 -> 2,348 resolved borrowers.
  4. Positions -> borrower-quarter panel: lowest lender mark (fvc_min), quarter change, lender dispersion, next-quarter non-accrual label.
  5. Story 1: label, instrument, size -> exact-label match on each lender's latest quarter -> quartiles, lender table, source rows with SEC links.
  6. Story 2: quarter, capacity -> sort by fvc_min -> list with change, NEW marker, lender marks, filing links, hindsight check.

Mark = sum(fair value) / sum(cost) per lender on debt rows: not netting, not equity, cost above zero.

Hypotheses, one per tackled sub-problem

1 · NO TAPE

Before -> after
64 filings read one by one -> one table of 42,830 positions with an accession per row
Hypothesis
If every schedule is parsed into one schema, then comparables and review lists can be computed across 8 lenders, because the filings already hold position-level marks and spreads.
Metric
Money-field accuracy on a frozen audit sample. Up. Baseline: 48 of 48 on principal, cost and fair value. Guardrail: below 0.90 on any money field means abandon the tape (README kill rule).
Test
Redraw the audit each new quarter, rows checked against the filing text.

2 · NAMES DON'T MATCH

Before -> after
each lender's spelling -> one borrower id across lenders
Hypothesis
If names are resolved with measured precision, then one borrower's marks from several lenders sit side by side, because a wrong merge would show a fake disagreement.
Metric
Pair precision at the chosen threshold. Up. Baseline 0.9855, n=69. Guardrail: transitive component precision, baseline 0.85, n=20.
Test
Fresh labelled draw, threshold fixed before labelling. Below 0.95 means stop (README kill rule).

3 · OPAQUE COMPARABLES

Before -> after
a quoted spread -> quartiles, lender table and source rows with SEC links
Hypothesis
If the spread comes with its lenders and rows, then the underwriter answers committee's "says who?" from the screen, because each row links to the filing.
Metric
Time to answer a sourcing question on a proposed spread. Down. Baseline unobserved.
Test
Two underwriters, 5 mock committee questions, broker notes vs the screen.

4 · ONE LENDER AS A MARKET

Before -> after
a bucket median read as market -> lender count first, one-lender warning, nearby labels listed but not merged
Hypothesis
If the screen names whose book drives the number, then fewer single-lender medians reach committee as "market", because the warning appears before the quartiles.
Metric
Share of cited comparables resting on one lender. Down. Baseline unobserved.
Test
Same mock session: count medians cited without their lender count.

5 · UNSIZED REVIEW LIST

Before -> after
no ranked list -> capacity-sized list, lowest lender mark first
Hypothesis
If the analyst reviews the 15 lowest-marked names, then more reviewed names turn non-accrual next quarter than a random 15, because a lender's mark below cost is its own filed admission of stress.
Metric
Share of the 15 flagged non-accrual next quarter (precision@15). Up. Baseline: 3 of 15 (2025-12-31), 1 of 15 (2026-03-31), against base rates of 22 of 1,423 and 19 of 1,415. The analyst's own list: unobserved.
Test
Analyst's list vs this list on the same quarter, outcome from the next filing.

6 · HIDDEN CHANGE

Before -> after
reopen last quarter's filing -> mark change, NEW marker, each lender's mark and filing link per row
Hypothesis
If each row shows what moved and links its filing, then the analyst spends less time per name before deciding to escalate, because the diff and source are on one line.
Metric
Minutes per reviewed name. Down. Baseline unobserved.
Test
Time one analyst on 15 names with filings only vs with the list.

Terms. Non-accrual: the lender stops recognising interest. NEW: absent from the prior quarter's list at the same capacity, not newly distressed.

Observed in the build
  • Coverage: 8 BDCs, 8 quarter ends from 2024-09-30 to 2026-06-30, 64 filings (16 10-K, 48 10-Q), 42,830 position rows, 2,348 resolved borrowers. Source: tools.coverage() on showcase/data. Supports 1.
  • Parse audit: 48 of 48 correct on principal, cost and fair value, Wilson 95% CI [0.9259, 1.0000] each. In-population sample drawn by the parser author. Source: eval/parse_audit_results.json. Supports 1.
  • Entity resolution: pair precision 0.9855 (68 of 69), CI [0.9224, 0.9974]; recall 0.9315 on 73 labelled true pairs; transitive precision 0.85 (17 of 20), CI [0.6396, 0.9476]. Threshold 93 chosen in-sample. 187 borrowers held by 2+ BDCs at 2026-06-30. Source: eval/er_results.json. Supports 2.
  • Story 1, Software first lien: 5 positions, 2 lenders (GBDC 4, PSEC 1), median S+675. Thin. Source: get_comparables, asserted in tests/test_showcase.py. Supports 3, 4.
  • Story 1, Insurance first lien: 90 positions, 4 lenders, median S+475; ARCC supplies 52 of 90. Source: two_stories.lender_table. Supports 3, 4.
  • Story 1, Software and Services first lien: 193 positions, all ARCC: one lender's book. Source: get_comparables. Supports 4.
  • Story 2, 2026-03-31: 15 names, 5 new since 2025-12-31; 1 of 15 flagged non-accrual next quarter, Wilson CI [0.01, 0.30]; base rate 19 of 1,415. Source: two_stories.hindsight. Supports 5, 6.
  • Story 2, 2025-12-31: 3 of 15, CI [0.07, 0.45]; base rate 22 of 1,423. Both quarters match the archived baseline precision@15 (0.200, 0.067) in eval/model_results.json, checked by a test. Supports 5.
  • Story 2, all 7 quarters: hits of labelled listed names range from 0 to 4. Three quarters show 0. Supports 5 weakly.
  • Tests: 12 passed (7 new for the two-story app, 5 existing), including AppTest renders with no exception. Local server health returned 200.
Limits and trade-offs
  • ML result: XGBoost did not beat the observed-mark baseline. 2,838 held-out borrower-periods, 41 positives. AUC 0.8160 baseline vs 0.7288 model; difference -0.0860, CI [-0.1948, 0.0273]. No difference interval excludes zero. Source: eval/model_results.json.
  • Failed release checks: cached model scores disagree with the model they cite on all 2,838 rows; historical lineage hashes and an ancestor manifest fail (M6.4). Cycle 11 ended LOOP, escalated STOP (D-018). The demo withholds scores; that hides the defect, it doesn't fix it.
  • Criteria state: 35 criteria in team/criteria.json v9: 27 PASS, 3 FAIL, 5 PENDING. The three product criteria (P1 to P3) are PENDING.
  • Users: no underwriter or analyst has used it. Every "before" is assumed.
  • Small samples: 15 names per quarter; one name moves precision by 0.067.
  • Data age: latest tape quarter 2026-06-30; the review panel stops at 2026-03-31 because labels need the next filing.
  • Parser limits: no currency column, some date-like industry labels hidden from the picker, one OBDC filing reconciles at -1.17%. Source: LIMITATIONS.md.
  • Vehicles: fund and joint-venture vehicles can appear on the review list; they aren't removed.
  • Visual review: no human has checked the pixels; tests assert page text.
