Deck Rank

Founders email pitch decks to a startup fund. Deck Rank ranks them so the best one gets read first. Every score quotes the slide it came from.

Who

                  Picks which decks get a first call this week.

Terms on this page

  • Pitch deck: slides a founder sends to ask for money.
  • First call: the first meeting between the fund and a founder.
  • Investment committee: the group at the fund that approves each investment.
  • The fund's own investors: the people and institutions whose money the fund invests.
  • Burn: cash a company loses each month.
  • Runway: months left before the company runs out of cash.
  • Must-have: a number the fund needs to see before a first call.
  • Fund weights: how much each score category counts, agreed once by the team.

User stories

  1. As a junior investor, I want decks ranked as soon as they're uploaded, with each number tied to its slide, so that I call the best fit first.
  2. As a junior investor, I want missing must-have numbers flagged with a drafted request to the founder, so that the first call doesn't start with basic questions.
  3. As the head of the fund, I want every rank to show its formula and sources, so that each yes or no to a company holds up with the investment committee and the fund's own investors.

Value equation

Would they use it? value = (outcome x likelihood it works) / (delay x effort & what they give up)

Problem

The best decks founders send in wait too long for a first call. Faster funds reach the founder first.

Why:

  1. Speed. Around 50 decks a week (assumed) are read in the order they arrive, each in full. The best one can sit behind 49 others.
  2. Consistency. Each junior investor ranks in their head, so two of them can pick a different "best".
  3. Evidence. When the investment committee asks "why this one?", the junior investor reopens the deck.
  4. Gaps. Decks leave out must-have numbers, and nobody notices until the first call.
  5. Memory. The reason a company was turned down is buried in email.

This build tackles 1 to 4. Memory is a non-goal for now.

Fix

  1. The deck PDF is split into one chunk per slide.
  2. Fixed rules pull out the numbers first, using text patterns, tables and slide layouts.
  3. An AI language model fills only the numbers still missing. Its quote must match the slide text exactly, or the value is rejected.
  4. Each value is stored with its source slide, the version of the code that read it, and the date.
  5. The score is a weighted average multiplied by the lowest must-have score divided by 5. So one weak must-have pulls the whole score down.
  6. The junior investor gets a ranked list, a scorecard (score breakdown with sources) per company, and next steps for missing data.

Scope

  • PDF decks that founders send in
  • Numbers pulled out with the quote they came from
  • Weighted score, must-have cap, fund weights plus personal weights
  • Ranked list, scorecard, junior investor can override a value with a reason
  • Missing-data flag plus a drafted founder email for the junior investor to review
  • Data older than 180 days flagged, quote re-checked on refresh

Non-goals

  • Finding companies that haven't sent a deck. That's Alpha Scout
  • Memory (sub-problem 5): why a company was turned down. The status log keeps date, who and score, not the reason
  • Sending email automatically
  • Deciding to invest or pass. The junior investor decides
  • Valuing the company, syncing with the fund's contact database (CRM)

Hypotheses, one per sub-problem

1 · SPEED

Before -> after
read in arrival order, in full -> ranked on upload, best first
Hypothesis
If decks are read and ranked on upload, then the best-fit deck gets a first-call decision sooner, because the junior investor starts at the top of the list instead of reading in arrival order.
Metric
Time from deck received to first-call decision, top 5 decks. Down. Baseline unobserved. Must not get worse: the number of top-10 companies later turned down stays flat or goes down.
Test
Two junior investors, same 20 decks, arrival order vs ranked list. "Top 5" = the 5 decks they'd call first after reading all 20.

2 · CONSISTENCY

Before -> after
ranking in each junior investor's head -> one shared formula and fund weights, personal view kept separate
Hypothesis
If every junior investor starts from the same fund weights, then two investors' top 10 lists overlap more, because the ranking rule is written down instead of remembered.
Metric
Top-10 overlap between two junior investors on the same batch. Up. Baseline unobserved.
Test
Same 20 decks. Compare top-10 overlap when ranked by hand vs with the fund weights.

3 · EVIDENCE

Before -> after
reopen the deck -> formula, inputs and source quote per score
Hypothesis
If every score shows its formula and source quote, then the junior investor answers the committee's "why this one?" faster, because the evidence is one click away.
Metric
Time to answer a "why" question on a ranked company. Down. Baseline unobserved.
Test
Practice investment committee with 5 "why" questions, deck only vs scorecard.

4 · GAPS

Before -> after
missing must-have found on the first call -> flagged at upload, moved to the bottom, founder email drafted for review. Data older than 180 days flagged
Hypothesis
If missing must-haves are flagged at upload with a drafted request, then fewer first calls start with data still missing, because the request goes out the day the deck arrives.
Metric
Share of first calls with a must-have still missing. Down. Baseline unobserved.
Test
Count it across the same 20-deck batch.

Observed in the build

  • Sample deck: 12 slides produced 49 values, all from the fixed rules. They covered 9 of 12 target numbers. The AI model was asked for the other 3 and returned none rather than guess.
  • Speed: upload to extracted values took 11 to 13 seconds, over 3 runs on the same deck. This supports "ranked on upload". It says nothing yet about time to a first-call decision.
  • Worked example: a Financials score of 3.16 out of 5, built from four inputs: 71% gross margin (revenue left after direct costs), 24 months of runway, revenue compared with burn, and funding stage.
  • Tests: 66 unit tests (small automated code checks). One fails if any stored quote doesn't appear in its source slide.

Limits

  • Data: three fictional companies. No real decks from founders yet.
  • Users: no junior investor has tested it. Every "before" is assumed, not observed.
  • Accuracy: the numbers it pulls out haven't been compared with decks checked by hand.
  • Coverage: only Financials has its own formula. Founders, Market and Tech Moat (how hard the tech is to copy) still use a generic weighted average.
  • Ranking quality: hypothesis 1 only helps if the ranking is right. If ranks are wrong, faster isn't better, so the accuracy test comes before the speed test.
