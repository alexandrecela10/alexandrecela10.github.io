Who

ANALYST   early-stage VC fund. decides which inbound decks get a first call this week
VC CEO    decides where analyst time goes. answers to LPs

User stories

  1. As an investment analyst, I want inbound decks ranked on upload with each value tied to its slide, so that I call the best fit first.
  2. As an investment analyst, I want missing must-have data flagged with a drafted founder request, so that the first call doesn't start with basic questions.
  3. As a VC CEO, I want every rank to show its formula and sources, so that pass and pursue decisions hold up with IC and LPs.

value = (outcome x likelihood) / (delay x effort & sacrifice)

Problem

The best inbound deals wait too long for a first call, and faster funds reach the founder first.

Why:

  1. Speed. Around 50 decks a week (assumed) are read in arrival order, each in full. The best one can sit behind 49 others.
  2. Consistency. Each analyst ranks in their head, so two analysts can pick a different "best".
  3. Conviction. When IC asks "why this one?", the analyst reopens the deck.
  4. Gaps. Decks miss must-have data, and it only comes up on the first call.
  5. Memory. Why a company was passed on is buried in email.

This build tackles 1 to 4. Memory is a non-goal for now.

Fix

  1. The deck PDF is split into one chunk per slide.
  2. Rules extract the metrics first, using text patterns, tables and slide layouts.
  3. A language model fills only the metrics still missing. Its quote must match the slide text exactly, or the value is rejected.
  4. Each value is stored with its source slide, extractor version and date.
  5. The score is a weighted average multiplied by the lowest must-have score divided by 5, so one weak must-have pulls the whole score down.
  6. The analyst gets a ranked queue, a scorecard per company and follow-up actions for missing data.

Scope

  • Inbound PDF decks
  • Metric extraction with source quote
  • Weighted score, must-have cap, house + personal weights
  • Ranked queue, scorecard, analyst override with reason
  • Gap flag + drafted founder email for analyst review
  • Stale-data flag at 180 days, quote re-checked on refresh

Non-goals

  • Finding companies that haven't pitched. That's Alpha Scout (outbound)
  • Memory (sub-problem 5): why a company was passed. The stage log keeps date, who and score, not the reason
  • Sending email automatically
  • Invest / pass decisions. Analyst decides
  • Valuation, CRM sync

Hypotheses, one per sub-problem

1 · SPEED

Before -> after
arrival order, read in full -> ranked on upload, best first
Hypothesis
If decks are extracted and ranked on upload, then the highest-fit deck gets a first-call decision sooner, because the analyst starts at the top of the queue instead of reading in arrival order.
Metric
Time from deck received to first-call decision, top 5 decks. Down. Baseline unobserved. Guardrail: top-10 companies later passed on stays flat or goes down.
Test
Two analysts, same 20 decks, arrival order vs ranked queue. "Top 5" = the 5 decks they'd call first after reading all 20.

2 · CONSISTENCY

Before -> after
ranking in each analyst's head -> one house formula and weights, personal view kept separate
Hypothesis
If every analyst starts from the same house weights, then two analysts' top 10 overlap more, because the ranking rule is written down instead of remembered.
Metric
Top-10 overlap between two analysts on the same batch. Up. Baseline unobserved.
Test
Same 20 decks. Compare top-10 overlap by hand vs with the house view.

3 · CONVICTION

Before -> after
reopen the deck -> formula, inputs and source quote per score
Hypothesis
If every score shows its formula and source quote, then the analyst answers IC's "why this one?" faster, because the evidence is one click away.
Metric
Time to answer a "why" question on a ranked company. Down. Baseline unobserved.
Test
Mock IC with 5 "why" questions, deck only vs scorecard.

4 · GAPS

Before -> after
missing must-have found on the first call -> flagged at upload, sorted to the bottom, founder email drafted for review. Stale data flagged at 180 days
Hypothesis
If missing must-haves are flagged at upload with a drafted request, then fewer first calls start with data still missing, because the ask goes out the day the deck arrives.
Metric
Share of first calls with a must-have still missing. Down. Baseline unobserved.
Test
Count it across the same 20-deck batch.

Observed in the build

  • Sample deck: 12 slides produced 49 values, all from the rules, covering 9 of 12 target metrics. The language model was asked for the other 3 and returned none rather than guess.
  • Speed: upload to extracted values took 11 to 13 seconds, over 3 runs on the same deck. This supports "ranked on upload". It says nothing yet about time to a first-call decision.
  • Worked example: a Financials score of 3.16 out of 5, built from four inputs: 71% gross margin, 24 months of runway, revenue over burn, and funding stage.
  • Tests: 66 unit tests. One fails if any stored quote doesn't appear in its source slide.

Limits

  • Data: three fictional companies. No real deal flow yet.
  • Users: no analyst has tested it. Every "before" is assumed, not observed.
  • Accuracy: extraction hasn't been measured against hand-labelled decks.
  • Coverage: only Financials has its own formula. Founders, Market and Tech Moat still use a generic weighted average.
  • Ranking quality: hypothesis 1 only helps if the ranking is right. If ranks are wrong, faster isn't better, so the accuracy test comes before the speed test.
